# WebSockets to Java via websockify

This repository offers a minimal example of how to create a simple
[Java](http://www.java.com) server application that accepts sockets using both
[TLS](https://en.wikipedia.org/wiki/Transport_Layer_Security) and
[WebSockets](https://en.wikipedia.org/wiki/WebSocket) via
[websockify](https://github.com/novnc/websockify).

## Status

This project is not currently working. It is offered as a minimal reproducible
example for debugging.

## Download, Build, and Run

This example uses [Docker Compose](http://docker.com) to simplify and
standardize all of the technologies involved:
```
git clone https://github.com/sgware/wss-test.git
cd wss-test
docker compose build
docker compose up
```
Then navigate to [https://localhost](https://localhost) to see an example of a
WebSocket connecting to the Java server. You will probably receive a warning
about the insecure self-signed certificate; accept it to view the page.

## Files of Note

The self-signed public/private key pair is generated by
[`self_sign.sh`](root/self_sign.sh) during the build. It is meant to mimic the
process of obtaining a real public/private key pair. It generates:
- `/etc/ssl/private/example-ca.key`, the private key for a local Certificate Authority
- `/etc/ssl/certs/example-chain.pem`, the public key (certificate) for the local Certificate Authority
- `/etc/ssl/private/example-private.pem`, the server's private key
- `/etc/ssl/certs/example.csr`, a Certificate Signing Request
- `/etc/ssl/certs/example-public.pem`, the server's public key (certificate)
- `/etc/ssl/certs/example-fullchain.pem`, a concatenation of the public Certificate Authority and server certificates

The [`keystore.sh`](root/opt/echo/keystore.sh) shell script imports the server's
public and private keys into a keystore that the JVM can use. This runs during
the build.

The [Java echo server](root/opt/echo/src/EchoServer.java) can be found in
[`/opt/echo`](root/opt/echo). It accepts TLS sockets on port 9000 and simply
sends back the first message sent to each socket. It also prints the stack trace
of any exceptions that are thrown. The `src` directory is mounted as a volume so
you can edit it from outside the container. From inside the container, there is
a shell scripts to [compile](root/opt/echo/compile.sh) it which runs during the
build. There is a shell script to [run](root/opt/echo/run.sh) it which runs when
the container starts.

The [`websockify.sh`](root/opt/echo/websockify.sh) shell script starts
websockify and writes its log to `/var/log/websockify.log`. It listens on port
9001 and targets the Java echo server on port 9000. This script runs when the
container starts.

A simple [webpage](root/var/www/example/public_html/index.html) uses JavaScript
to open a secure WebSocket on port 9001 and send a single message. If
successful, it prints the response sent from the server. The web root
[`/var/www/example/public_html`](/var/www/example/public_html) is also mounted
as a volume so you can edit it outside the container.
